# ClimbKit

Мобильное приложение для учёта личного альпинистского и скалолазного снаряжения.
Сейчас это работающий прототип на чистом HTML/CSS/JS, который нужно упаковать
в нативное Android-приложение через Capacitor.

Живая версия прототипа: https://stoika-gear-ilya-star.vercel.app

## Что это за продукт

Человек заводит своё снаряжение, приложение считает его возраст и наработку,
напоминает об осмотрах и не даёт ничего забыть при сборах на выезд и при
возвращении домой.

Целевая аудитория — частное лицо, а не клуб и не прокат. Поэтому нет аккаунтов,
нет сервера, нет синхронизации: все данные лежат на устройстве.

## Ключевые продуктовые решения (не менять без обсуждения)

**Никакого бекенда.** Данные одного человека, которые никто больше не читает.
Сервер добавил бы регистрацию, GDPR и риск, что через два года всё умрёт.
Перенос между устройствами сделан файлом: экспорт/импорт JSON в настройках.

**Срок службы задаётся группой категорий, а не типом предмета.**
Текстиль и защита — 10 лет эксплуатации плюс 5 лет хранения до первого
использования (два независимых счётчика, суммарно не более 15). Железо и
«разное» — срока нет вообще, только износ и осмотр раз в полгода.
Исключения из группы «Защита»: очки и перчатки — им производители ресурс не
назначают, они выведены через `LIFE_T`.

Принципиально: **не рисовать металлу фальшивую шкалу ресурса.** Если списывать
френды по возрасту, перестанут верить и настоящим срокам у верёвки.

**Наработка считается через выезды, а не отдельной кнопкой.**
Пользователь создаёт выезд, отмечает снарягу при сборах, жмёт «Собрано — в путь».
По возвращении отмечает всё снова и жмёт «Собрано — домой» — тогда каждому
предмету добавляются дни поездки. Ручной кнопки «день лазания» нет намеренно:
учёт должен вестись сам.

**Уведомления только локальные.** Никакого push и никакого сервера. Функция
`reminders()` в `app.js` возвращает готовый список «что и когда показать» —
она специально изолирована, чтобы при переносе на Capacitor подключиться к
системному планировщику один в один.

**Тон предупреждений мягкий.** «Обвязке 7 лет, посмотри стропы» — помощь.
«ПРОСРОЧЕНО» на красном — тревожность, от которой приложение удаляют.
Красный цвет используется скупо, только для реальных проблем.

## Архитектура

Три файла, никакой сборки, никаких фреймворков:

- `www/index.html` — оболочка, все стили, спрайт из 57 SVG-иконок
- `www/i18n.js` — словарь `TXT` для ru и en (~140 ключей)
- `www/app.js` — вся логика

Рендер устроен максимально просто: состояние в двух объектах, функции экранов
возвращают строку HTML, `render()` перерисовывает `#view`, `#modal`, `#nav`
целиком. Обработчики — инлайновые `onclick`, функции глобальные. Это осознанный
выбор ради читаемости прототипа; при росте кода первым делом стоит вынести
делегирование событий, а не тащить фреймворк.

### Состояние

`D` — данные, сохраняются в `localStorage` под ключом `climbkit-v4`:
```
D = { onboarded, lang, theme, notif:{insp,trip,home}, items[], trips[], events[], seq }
```

`S` — состояние интерфейса, не сохраняется: текущий экран, вкладка, открытая
модалка, фильтры, черновики форм.

Предмет:
```
{ id, type, name, size, buy, made, days, falls, factor, weight,
  status: 'ok'|'warn'|'alert'|'retired', lastInsp, notes, photos[],
  serial?, reason?, reasonText? }
```
Даты хранятся строками `YYYY-MM-DD`. `reason` — ключ словаря (`rMelt`, `rAge`,
`rFall`, `rWear`, `rOther`), а не готовый текст, иначе он не переведётся.

Выезд:
```
{ id, name, from, to, items[], picked{}, state: 'draft'|'ready'|'away'|'done' }
```
`ready` выставляется автоматически, когда отмечено всё. Удалить выезд можно
только пока он не отправлен (`draft` или `ready`).

Событие истории:
```
{ d, k:'a'|'o'|'i', tk: ключ_словаря, m: подпись, mx?: подставляемое, rk?: причина, item: id }
```
Тексты событий тоже хранятся ключами — иначе история не переведётся при смене
языка.

### Локализация

Язык берётся из `navigator.language`, вручную переключается в настройках
(`D.lang`: `sys` | `ru` | `en`). Функция `t(key, a, b)` подставляет `%A` и `%B`.
Названия категорий лежат прямо в `TYPES[k].ru` / `.en`.

Демо-данные генерируются в `seed()` на языке системы. Названия предметов — только
бренды и модели, без слов вроде «Обвязка», чтобы не переводить пользовательские
данные.

### Темы

Светлая и тёмная палитры — CSS-переменные, переключение через
`document.documentElement[data-theme]`. Тёмная не инверсия светлой: графит
вместо чёрного, приглушённые акценты. Есть слушатель `prefers-color-scheme`.

## Что нужно сделать дальше

### 1. Собрать Android-приложение

```bash
npm install
npx cap add android
npx cap sync
cd android && ./gradlew assembleDebug
```
APK окажется в `android/app/build/outputs/apk/debug/app-debug.apk`.

Либо через GitHub Actions: workflow уже лежит в `.github/workflows/android.yml`,
собирает debug-APK и кладёт его в артефакты.

### 2. Перенести фото из localStorage в файловую систему — ВАЖНО

Сейчас фотографии хранятся base64-строками прямо в `localStorage`, лимит которого
около 5 МБ. Десяток снимков его переполнит, и `save()` начнёт молча падать
(ошибка проглатывается в `try/catch`).

Нужно: сохранять фото через `@capacitor/filesystem` в каталог приложения,
а в предмете держать только имена файлов. Функции для правки: `addPhoto()`,
`deletePhoto()`, `mPhoto()`, плюс экспорт/импорт в `exportBackup()`/`importBackup()`.

Заодно стоит перевести `D` с `localStorage` на `@capacitor/preferences` —
у него нет лимита в 5 МБ.

### 3. Подключить настоящие локальные уведомления

`reminders()` уже отдаёт список напоминаний. Нужно при каждом запуске и после
изменения данных пересчитывать его и планировать через
`@capacitor/local-notifications`:

- осмотр — когда с последнего прошло 6 месяцев (`item.lastInsp`)
- сборы на выезд — за 2 дня до `trip.from`, если выезд ещё `draft`/`ready`
- сборы домой — за день до `trip.to`, если выезд `away`

Перед планированием отменять ранее запланированные, иначе они будут дублироваться.
Уважать переключатели `D.notif.insp` / `.trip` / `.home`.
Функция `testNotification()` в текущем виде — веб-заглушка, её можно удалить.

### 4. Мелочи

- Кнопка «Назад» на Android должна закрывать модалку и возвращаться по экранам,
  а не выходить из приложения (`@capacitor/app`, событие `backButton`).
- Проверить безопасные зоны: сейчас используется `env(safe-area-inset-bottom)`,
  на Android нужен `viewport-fit=cover` и, возможно, edge-to-edge.
- Иконки приложения генерируются из `www/icon.svg` (`@capacitor/assets`).

## Чего делать не нужно

- Не добавлять аккаунты, облако и синхронизацию.
- Не добавлять ленту, соцфункции и партнёрские ссылки на магазины: приложение
  говорит «пора менять» — и тут же продаёт. Это уничтожает доверие.
- Не делать автоопределение срывов по акселерометру: телефон лежит в кармане,
  ложные срабатывания неизбежны, а фактор рывка из этих данных не считается.
- Не заводить учёт чужого и клубного снаряжения — это другой продукт, там уже
  есть Scannable и GearLog.

## Стиль

Цвета — известняк и графит, один акцент петроль. Числа набраны IBM Plex Mono:
журнал снаряжения — прибор, цифры должны выравниваться по разрядам. Интерфейс —
Archivo.

Шкала ресурса нарисована как измерительная лента, а не как обычный прогресс-бар:
человек видит не «30%», а положение на отрезке жизни.

Логотип — баул с горным хребтом внутри. Он же серая подложка в пустых состояниях,
и он же кликабельный: нажатие заводит первый предмет.
